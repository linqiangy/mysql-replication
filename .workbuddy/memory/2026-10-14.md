# 2026-10-14

## bincat 项目（MySQL binlog 监听服务）从零到 M4 完成

选型结论：不用 Canal/Debezium 现成方案（字段过滤/动态配置不满足、部署重），
基于 go-mysql-org/go-mysql 库自建（Go），协议解析交给库、业务层自研。

### 已完成（4 个 commit，全部端到端验证）

- **M1 核心管线**：canal 接入、表/操作/字段三级过滤（watch_fields 对比 before/after）、
  console sink、位点存元数据库、断点续传。本机 MySQL 9.7 验证通过。
- **M2 生产投递**：http/kafka/rabbitmq sink + 阻塞式 at-least-once。
  修复关键 bug：AdvanceIdle 越过阻塞批次推位点会丢消息（改为全部走 worker 队列）。
  验证：sink 挂→位点冻结；恢复→补发+位点推进。
- **M3 Web 后台**：gin+JWT、admin/user 角色、规则按 owner 隔离、热更新
  （API 建规则立即生效不断流）、Vue3+Element Plus 单文件 SPA（CDN+go:embed，
  无需 Node 构建）、数据源连接测试（校验 binlog 前置）、审计日志。
- **M4 指标**：Prometheus（binlog_delay/events_total/filtered_total/sink_batches/
  reconnects/pipeline_up/checkpoint_pos）+ pprof。
